## Implemented fail-closed path

1. `worker_payload.require_real_worker=true` or worker-process env `MAX_AGENT_REQUIRE_REAL_WORKER=1` activates the requirement. Payload strings `1`, `true`, and `yes` are accepted case-insensitively; the environment switch is exactly `1`.
2. `CliWorker` checks the selected vendor immediately after `choose_vendor`. Explicit `stub` and `auto` fallback to stub return `ok=false`, `adapter_failure=real_worker_required`, `cli_invoked=false`, and `real_cli_invoked=false` before workspace/worktree creation.
3. The adapter also refuses a completed result if the requirement is active but its real-invocation marker is false. Every CLI report includes `require_real_worker`.
4. Verification adds a `require_real_worker` check when the requirement is active and outputs contain `real_cli_invoked`. Finalization repeats the check before any transition to `succeeded`. Non-CLI mock outputs lack the marker and retain existing behavior.
5. With neither payload nor environment requirement set, the existing local stub demo still succeeds for development and CI.

`real_worker_required` is non-recoverable: retrying the same stub selection cannot make it a real run.

## Run a live Claude or Codex drill

Use a disposable checkout/database, non-production credentials, and an operator-approved timeout, quota, cost, and network boundary. Export the selected provider credential through the operator's normal secret mechanism; do not paste it into shell history or evidence. Then run exactly one vendor drill:

```bash
scripts/real_cli_e2e_drill.sh --real --vendor claude
# or, after separate OpenAI/Codex authorization:
scripts/real_cli_e2e_drill.sh --real --vendor codex
# Grok and authorized auto-selection are also supported:
scripts/real_cli_e2e_drill.sh --real --vendor grok
scripts/real_cli_e2e_drill.sh --real --vendor auto
```

The script uses the real application entry point (`python -m max_agent.cli.main`) for `init-db`, `create`, one `run`, `status`, and `events`. It sets both `MAX_AGENT_ALLOW_EXTERNAL_CLI=1` and `MAX_AGENT_REQUIRE_REAL_WORKER=1` only for the drill process, and creates the task with payload `require_real_worker=true`.

Raw JSON and a redacted-field summary are retained under `/tmp/max-agent-real-cli-e2e.*`:

- `create.json`, `run.json`, `status.json`, `events.json`
- `real-cli-result.json`: task/status/verification, selected vendor, probes, adapter failure, `cli_invoked`, `real_cli_invoked`, `require_real_worker`, and artifact-manifest path

Live acceptance requires all of:

```text
status == "succeeded"
verification.passed == true
real_cli_invoked == true
require_real_worker == true
vendor == requested real vendor (or a real vendor selected by auto)
adapter_failure == null
```

The drill exits non-zero if a task reports `succeeded` without `real_cli_invoked=true`, if verification fails, or if another execution error occurs. `cli_unavailable`, `cli_not_authorized`, or `real_worker_required` with no real invocation is reported as **SKIP**, not PASS. Inspect `probes` and `adapter_failure`; do not convert an unavailable or unauthenticated vendor into stub success.

The equivalent manual commands are documented in [../grok-e2e.md](../grok-e2e.md), section 6. In every case inspect the journaled `worker_output` and `.max-agent/manifest.json`; never infer a real provider call from terminal status alone.

## Isolation boundary

A separate git worktree is only a separate checkout. **Worktree != OS/user/container/VM isolation.** Grok/Codex/Claude sandbox or permission flags do not create a VM boundary, and provider APIs may use the network. Live drills still require a disposable environment and non-production targets.
