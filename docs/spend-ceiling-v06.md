# Spend ceiling foundation (Issue #82)

The first bounded path is one fixed, text-only OpenAI Responses request. `SingleRequestPlan` fixes model, input and maximum output tokens, disables tools and automatic truncation, and computes a SHA-256 digest of the create payload. `prepare_single_request_bound` accepts an injected input-token counter, checks a concrete account/model/price version, and calculates the worst-case Decimal amount at full input and output rates per million tokens. Cached input uses the higher configured input rate. Storage precision is rounded **up** to 18 decimal places. The quote must fit both the model context and the task's original-unit ceiling.

The Responses API's `max_output_tokens` includes reasoning and other generated tokens; its [input-token count endpoint](https://developers.openai.com/api/docs/guides/token-counting) accepts the request input format and returns the model's count. The [create API reference](https://developers.openai.com/api/reference/resources/responses/methods/create) defines the output cap. These facts support the narrow single-request calculation, not a spending guarantee for a multi-call coding agent.

**Current status:** this module is an offline quote only. The `InputTokenCounter` can be a fake; MAX does not yet authenticate a provider count response, persist the bound, reserve this derived amount in the claim transaction, or send the exact digested payload through a one-call adapter. A configured HTTPS price source is evidence to review, not proof that the rate covers negotiated pricing, taxes or new billing dimensions. No paid route can use this code yet. The production `spend_ceiling_unenforced` gate remains closed.

Next implementation gate: pin and review the account's price version and billable dimensions; count exactly the payload to be sent; durably bind digest, count and cap to the attempt; reserve the derived amount before dispatch; permit exactly one request with the same digest and maximum output cap; reconcile measured usage, and retain the hold if the response is absent or ambiguous. Coding CLIs additionally require a gateway and blocked direct provider egress, since a timeout or one bound model flag does not cap their number of paid requests.
